# API Reference

Base URL (local): `http://localhost:3000`
All request and response bodies are JSON. Data is stored in memory (see the README for limitations).

## Order object

| Field | Type | Rule |
|---|---|---|
| id | string | Generated by the server, cannot be edited |
| customerName | string | Required, trimmed, not blank |
| phone | string | Required, trimmed, not blank (kept as text) |
| productName | string | Required, trimmed, not blank |
| quantity | number | Positive integer, minimum 1 |
| unitPrice | number | Finite number, minimum 0, at most two decimal places |
| total | number | Calculated by the server (quantity x unitPrice, using integer cents) |
| status | string | `Pending`, `Preparing`, or `Delivered` |

## Endpoints

| Method | Endpoint | Success | Errors |
|---|---|---|---|
| GET | /api/orders | 200 | none |
| POST | /api/orders | 201 | 400 |
| GET | /api/orders/[id] | 200 | 404 |
| PATCH | /api/orders/[id] | 200 | 400, 404 |
| DELETE | /api/orders/[id] | 204 (no body) | 404 |

### GET /api/orders
Returns an array of all orders.

### POST /api/orders
Creates an order.

Request:
```json
{
  "customerName": "Demo Customer",
  "phone": "DEMO-001",
  "productName": "Vanilla Candle",
  "quantity": 3,
  "unitPrice": 8
}
```

Response `201`:
```json
{
  "id": "server-generated-id",
  "customerName": "Demo Customer",
  "phone": "DEMO-001",
  "productName": "Vanilla Candle",
  "quantity": 3,
  "unitPrice": 8,
  "total": 24,
  "status": "Pending"
}
```

The server ignores any `id`, `total`, or `status` sent by the client. A new order always gets a server-generated ID, a server-calculated total, and the status `Pending`.

### GET /api/orders/[id]
Returns the matching order with `200`, or `404` if the ID does not exist.

### PATCH /api/orders/[id]
Updates only the fields that are sent. Editable fields: `customerName`, `phone`, `productName`, `quantity`, `unitPrice`, `status`.

Request:
```json
{ "quantity": 4, "status": "Preparing" }
```

Response `200`: the full updated order, with `total` recalculated (32 in this example).

Rules:
- Omitted fields keep their current values.
- Every supplied field is validated before anything is stored.
- A rejected update leaves the stored order unchanged.
- An empty body returns `400`.
- `id` and `total` in the body are ignored. The server always keeps its own ID and recalculates the total.
- An unknown ID returns `404`.

### DELETE /api/orders/[id]
Removes the order. Returns `204` with no body, or `404` if the ID does not exist.

## Error format

Every error response contains a message:

```json
{ "error": "Quantity must be a positive integer" }
```

| Status | When |
|---|---|
| 400 | Malformed JSON, failed validation, or an empty PATCH body |
| 404 | The order ID does not exist |

## Validation messages

- Customer name / Phone / Product name is required and cannot be blank
- Quantity must be a positive integer
- Unit price must be a number of 0 or more
- Unit price can have at most two decimal places
- Status must be one of: Pending, Preparing, Delivered
- Request body must be valid JSON
- Request body must be a JSON object
- No editable fields provided

## Where the rules live

- `lib/orders.ts`: validation, total calculation, and the in-memory store
- `app/api/orders/route.ts`: GET and POST
- `app/api/orders/[id]/route.ts`: GET, PATCH, and DELETE
